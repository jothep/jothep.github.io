Change the workflow within the project’s boundaries.

Moving from Bamboo to GitLab CI/CD required reviewing the old steps, their dependencies and expected results. The workflow also needed prepared runner hosts and the project’s required security checks.

a.

Script boundaries / Maintainability

Why did you restructure the scripts instead of copying the Bamboo steps into GitLab?

My answer

I reviewed what each step did, what it depended on and what result it should produce. The necessary tasks stayed, but scripts that mixed several responsibilities needed a different structure.

I rewrote most of the scripts, separating common functionality into reusable scripts and templates while keeping task-specific work distinct. This fitted the client’s approach to shared functionality and made the pipeline easier to follow.

For example, I reused the Helm deployment script across SIT, UAT and production. HPB also supplied shared functions such as image scanning, which I reused in the pipelines. I integrated those functions rather than writing them myself.

b.

Environment boundaries / Release approach

How did the project’s access restrictions shape your release approach?

My answer

Access between environments was strictly restricted. In this project, SIT, UAT and production each built and deployed from the same code for a given release version, rather than promoting one immutable package or image.

I worked within those boundaries when rebuilding the pipelines. SIT deployed automatically, while UAT and production required manual confirmation. For the migration itself, I completed and validated SIT/UAT before progressing production and reused the work already prepared.

c.

Delivery ownership / Coordination

What did you own when some migration work required action outside your team’s access?

My answer

I mainly handled the migration and guided another engineer through some repeated scripts and steps. I prepared and coordinated restricted changes, while client support teams executed the operations outside our permitted access.

For the FOD integration issue, I supplied the details and requirements, followed up through the PO and support team, and used the agreed process to obtain vendor help. The vendor resolved its managed part. We completed the required configuration and validation, and finished the migration.
